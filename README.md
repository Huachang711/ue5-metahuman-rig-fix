# UE5 MetaHuman「创建完整绑定」失败完全解决指南

> 卡在「自动绑定面部网格体」、报「超时」、按钮变灰、日志报 `EOS_Initialize failed error:EOS_InvalidParameters` —— 一条原因，一个解法。

## 一句话结论

**项目名（文件夹名 / `.uproject` 文件名）里带中文，导致 EOS SDK 初始化失败。**

EOS 是 MetaHuman 云端认证的入口。它起不来，编辑器拿不到凭证，「帮我绑骨骼」的请求**一个都发不出去** —— 你看到的就是一直转圈。

把项目名改成纯英文后，绑定 **83 秒**跑完。

> 与网速、代理、重装、重登账号**都不是因果关系**。网络只需要能连通 Epic（判断标准：Epic 商店能正常打开）。

## 症状对照

点「创建完整绑定 / Create Full Rig」后，出现任意一种：

| 你看到的 | 具体情况 |
|---|---|
| 一直转圈 | 提示条写着「自动绑定面部网格体」，等十几分钟没变化 |
| 弹「超时」 | 约 90 秒后提示「面部自动绑定失败，代码为"超时"」 |
| 什么都不发生 | 进度条挂着，但 CPU 0%、风扇不响 |
| 按钮变灰 | 提示「资产处于绑定待处理状态」，预设/材质/建模全被锁 |

这四种看起来不一样，其实是同一个毛病。

---

## 为什么是这个原因

### 故障链条

UE 5.6 起，MetaHuman 的绑定不在本地算，而是**上传模型 → Epic 服务器计算 → 回传骨骼数据**。所以必须先完成身份认证：

```
项目名（ProductName）
   ↓  引擎启动时用它去 Epic「报到」
EOS 登录模块启动
   ↓  成功才拿得到 token
MetaHuman 云端授权（Consent）
   ↓
POST /v1/autorigs   发出「帮我绑骨骼」的请求
   ↓
服务器计算完成，回传数据
   ↓
本地构建 FaceMesh → 绑定完成

❌ 中文项目名在第 1 步就断了，后面 5 步一次都没执行
```

### 对照实验（同机器 / 同账号 / 同网络）

唯一变量是项目名：

| | 中文项目「角色」 | 英文项目「Character」 |
|---|---|---|
| EOS 初始化 | ❌ `EOS_Initialize failed error:EOS_InvalidParameters` | ✅ `ProductName=Character` |
| 登录结果 | ❌ `EOSSDK not initialized` | ✅ `Login complete: EOS_Success` |
| HTTP 请求 | 0 个 | ✅ `POST /v1/autorigs` |
| 结果 | 永远卡在第一步 | ✅ 83 秒绑定完成 |
| 资产体积 | 9 MB（未绑定） | 16 MB（含骨骼数据） |

**关键点**：EOS SDK 的 `ProductName` 参数直接取自项目文件名。这个名字只接受 ASCII，中文会被判定为非法参数，整个登录模块拒绝启动。

## 解决步骤（8 步）

### 前提：梯子先开起来

不做这步，后面每一步都会失败，**而且失败的样子跟「没改名」一模一样**，会让你误以为改名没用。

**判断标准**：打开 Epic 商店，内容能正常刷出来；或 Fab 面板能加载出东西。能 → 跳过这条。

不能 → 先把梯子调通。用什么、怎么配，你自己清楚就行，这里不展开。
同时只开一套，切换时要彻底关掉前一套（不是只关窗口）。

---

### 1. 检查项目名有没有中文

三样都得是英文：**文件夹名**、**`.uproject` 文件名**、**完整路径**。空格、日文、表情符号也不行。

```diff
- ❌ D:\Projects\角色\角色.uproject
+ ✅ D:\Projects\Character\Character.uproject
```

> **如果名字本来就是英文** → 病因不在名字，第三章不适用，直接看 [300 秒报错](#另一种情况300-秒报错不怪你) 那一节。

<details>
<summary>想先确认再动手？（可选的对照实验）</summary>

新建一个纯英文项目（如 `TestMH`）试一次，**但要同样把梯子开好、EOS 插件打开**，否则测试一定失败，反而误导你。

- 能绑上 → 确认是名字问题，放心改正式项目
- 绑不上 → 先把梯子和插件弄好，别急着动正式项目

验证完直接删掉即可。
</details>

---

### 2. 关掉 UE，备份一份

**先保存项目、彻底关闭 UE**，不然文件夹被占用，复制会报错、改名也会失败。

把整个项目文件夹复制一份，副本名字加 `_备份`，最好放到别的位置。

> 副本**不要打开、不要拿它测试**，它只是兜底用的。

---

### 3. 改名字，文件夹和 `.uproject` 必须一致

```
角色\            →  Character\
角色.uproject    →  Character.uproject
```

两个名字必须完全一致，否则 UE 会报「找不到项目文件」或打开成空项目。

---

### 4. 双击新的 `.uproject` 打开

模型、材质、蓝图都还在，**不会丢**（项目内部用相对路径）。

若弹出「是否重新关联 / 升级项目」，选「是」。

打开后确认：内容浏览器空白处右键，菜单里有没有 **MetaHuman**。没有的话 → `编辑 → 插件` 搜 `MetaHuman`，勾选 **MetaHuman Creator** 和 **MetaHuman**，重启编辑器。

---

### 5. 确认 `Online Subsystem EOS` 插件已启用

这个插件**默认关闭**，很多人从没开过。没开，登录照样起不来。

**开启路径**：`编辑 → 插件` → 搜 `EOS` → 勾选 **Online Subsystem EOS**（描述为 *Online Subsystem for Epic Online Services*）→ 点「重新启动」。

> ⚠️ **最容易勾错的地方**：列表里还有一项 `EOS Shared`，它只是底层运行库，**勾它不等于启用认证**。要勾的是 `Online Subsystem EOS` 这一行。

**开对了的日志特征**：

```
Mounting Engine plugin OnlineSubsystemEOS
Mounting Engine plugin SocketSubsystemEOS
```

> 这个插件**不是根因**。实测中即使勾了它，中文项目名照样报 `EOS_Initialize failed`。但它是 EOS 认证的配置来源，缺了也跑不起来。**两件事都得满足：插件开着 + 名字是英文。**

---

### 6. 看日志，确认「报到」成功

`窗口 → 输出日志`，搜 `EOSSDK`，找到：

```
[Boot] EOSSDK Platform Properties [... ProductName=你的英文项目名 ...]
```

看到 `ProductName=你的英文项目名` 就说明认证层通了。

如果看到 `EOS_Initialize failed`，或者压根搜不到 `EOSSDK` → 回第 3 步（改名）和第 5 步（插件）各查一遍。

---

### 7. 打开资产 → 清旧状态 → 点创建绑定

- 若「创建完整绑定」按钮是灰的、提示「绑定待处理」，先点 **「删除绑定」** 清掉旧状态（只清状态，不删模型）
- **视口里要有脸**，空资产先从左侧 `Presets` 拖一个进去
- 点「创建完整绑定」，浏览器会要求登录 Epic 账号 + 同意 MetaHuman 云服务条款

**浏览器没弹出来？分两种情况**：

- 之前授权过 → 凭证还在，不用重授，直接等结果
- 从没授权过 → 多半是默认浏览器打不开授权链接，换成 Chrome / Edge 再点一次

---

### 8. 等 1～3 分钟，然后组装

日志出现这行就代表成功：

```
Building Skeletal Mesh FaceMesh_0 / FaceMesh_2 ...
```

旁证：资产从 9 MB 涨到约 16 MB。

**确认绑定成功再进 Assembly**（标志：按钮不再转圈、左侧能正常调脸）。

组装：`Assembly` → 选 `UE_Optimize` → 质量 `Medium` → `Download Texture Sources` → `Assemble`。

> ⚠️ **顺序不能反**：下载纹理**不会**触发登录。新开编辑器后，必须先点一次「创建完整绑定」唤醒凭证，否则下载会报「用户未登录」。详见 [常见卡点](#常见卡点下载纹理报用户未登录)。

> `Download Texture Sources` 报错 → 先看梯子是不是断了，然后重试。这一步和绑定是两套服务。

## 按症状快速定位

| 你看到的提示 | 什么毛病 | 怎么处理 |
|---|---|---|
| 「MetaHuman Creator 核心数据与引擎一起安装」 | 装引擎时漏了数据包 | Epic Launcher → 库 → 引擎「选项」→ 勾 `MetaHuman Creator Core Data` → 应用 → 重启 |
| 弹窗列 4 个开关（Missing Project Settings） | 脸部骨骼超出默认渲染上限 | 点「启用缺失」→ 重启。这四个开关是硬性要求 |
| 点绑定无反应，日志只有「自动绑定面部网格体」 | ① 项目名中文 ② EOS 插件没开 | 日志搜 `EOSSDK`：搜不到 → 查第 3、5 步；搜到了 → 问题在别处 |
| 约 90 秒报「超时」 | 同上，认证没完成 | 同上 |
| 进度条挂着但 CPU 0% | 僵尸任务 | 关标签页重开；按钮灰就用「删除绑定」清状态 |
| 下载纹理报「用户未登录」 | 新会话还没唤醒登录 | 回编辑器点一次「创建完整绑定」，再下载。见 [下一节](#常见卡点下载纹理报用户未登录) |
| 正好 300 秒报 `Server Error` | Epic 服务端 bug | 见 [300 秒报错](#另一种情况300-秒报错不怪你) |

## 常见卡点：下载纹理报错

下载纹理有两个完全不同的坑，先分清是哪个：

| 报错 | 原因 | 跳到 |
|---|---|---|
| 用户未登录，请在下载源面部纹理前进行自动绑定 | 新会话没唤醒登录 | [用户未登录](#一用户未登录) |
| 源身体纹理下载失败，代码为「服务器错误」 | 并发连接池打满，排队超时 | [下载超时](#二下载超时服务器错误) |

### 一、用户未登录

点 `Download Texture Sources`，弹出两条错误：

```
用户未登录，请在下载源面部纹理前进行自动绑定
用户未登录，请在下载源身体纹理前进行自动绑定
```

#### 真实原因

**下载纹理这个动作不负责登录。** 它只检查「现在有没有登录」，没有就直接拒绝，连登录框都不弹。

新开编辑器后，EOS 的凭证不会自动加载，得等某个动作去唤醒它 —— 而这个动作是**「创建完整绑定」**。

#### 日志长这样

```
23:31:56  点下载纹理  → 用户未登录
23:32:25  点下载纹理  → 用户未登录
23:32:41  点下载纹理  → 用户未登录
23:34:05  点了「自动绑定面部网格体」
23:34:07  Login complete: EOS_Success      ← 登录在这里才发生
```

三次点击全是白费，因为登录动作发生在它们之后。

#### 解法

1. 回到 MetaHuman 编辑器（不是 Assembly）
2. 点一次 **「创建完整绑定」**
3. 等日志出现 `Login complete: EOS_Success`（通常 2 秒）
4. 再进 Assembly → 点 `Download Texture Sources`

**不会重跑云端**：凭证有效时它只做本地校验，秒完成。日志里的 `Refresh[Expires: 2027-04-16]` 说明刷新凭证有效期很长，所以平时不弹授权页，都是在后台静默续期。

#### 记住这个顺序

```
创建完整绑定（唤醒登录）→ 下载纹理 → 组装
```

每次新开编辑器都要先走一遍第一步。

---

### 二、下载超时（服务器错误）

登录成功后点下载，仍然失败，提示：

```
源身体纹理下载失败，代码为"服务器错误"
```

日志长这样：

```
GET .../areas/chest/textureTypes/underwear/.../resolutions/8k
    completed with reason 'ConnectionError' after 31.11s
libcurl error: 28 (Timeout was reached)
No more connections allowed to host
No connections available
Operation timed out after 30000 milliseconds with 0 bytes received
```

#### 不是带宽问题，也不是内存问题

三个关键线索：

| 线索 | 含义 |
|---|---|
| `0 bytes received` | 一个字节都没开始接收 —— 连接压根没建立起来 |
| `No connections available` | UE 对同一服务器的并发连接数已用满 |
| `after 31.11s` / `30000 ms` | 卡满 30 秒超时，**排队时间也算在里面** |

同时请求多张 8K 贴图（面部、身体、多套材质），连接池被打满，后面的请求只能排队，排队排队就超时了。

**8K 本身没问题**：一张 8K 贴图约 67 MB，5 MB/s 的线路 13 秒就能下完，30 秒绰绰有余。

#### 解法

1. **等 10 秒，再点一次下载** —— 连接释放后通常能过；已下完的部分有缓存，不会重下
2. 还失败 → **分辨率降到 4K** —— 减少并发压力，不是省带宽
3. 别降到更低，4K 对配置正常的机器完全够跑

## 另一种情况：300 秒报错（不怪你）

| | 本项目描述的问题 | 另一种问题 |
|---|---|---|
| 请求发出去了吗 | **没有，0 个** | 有，拿到 job id 了 |
| 卡多久 | 90 秒左右或直接不动 | **正好 300 秒** |
| 报什么 | 「超时」或无提示 | `Server Error` |
| 怪谁 | 项目名，能自己修 | Epic，修不了 |
| 识别特征 | 日志无 `ProductName=` 行 | `HTTP request timed out after 300.00 seconds` |

第二种是 Epic 官方论坛已确认的 bug，**5.6 / 5.7 / 5.8 都有，5.5 及以前没有**。300 秒硬编码在插件里，改配置文件无效（多人实测）。社区里零星有人说换网络环境能过、退出重登能过，但都不稳定，官方至今未修。

- 原始报告：<https://forums.unrealengine.com/t/metahuman-creator-in-editor-plugin-autorig-texture-download-fail-with-a-300s-http-timeout-server-error-from-non-us-regions-5-6-5-7-5-8-regression-from-5-5/2740392>
- 相关：<https://forums.unrealengine.com/t/error-not-logged-in-5-6/2542895>

## 避坑清单

| 记住这条 | 为什么 |
|---|---|
| 项目名、路径全用英文 | 中文会让登录模块起不来，云端功能全废 |
| 文件夹名和 `.uproject` 名要一致 | 不一致会导致项目打不开或变空项目 |
| 绑定前先看日志有没有 `EOSSDK` | 登录没起来，点一百次也没用 |
| 只点一次，别连点 | 多任务叠加，前一个卡住会锁死按钮 |
| 卡住了先关标签页 | 死掉的任务会存进资产，越点越乱 |
| 渲染设置用「启用缺失」 | 手改容易漏项，少开一个就显示错乱 |
| 梯子得开着 | 判断标准是 Epic 商店能正常打开。但梯子只负责搭桥，治不了中文名的病 |
| 同时只开一套 | 两套一起开会互相干扰 |
| `Online Subsystem EOS` ≠ `EOS Shared` | 前者是登录模块（默认关），后者只是零件 |
| 下载报「服务器错误」先重试 | 多半是并发连接排队超时，不是下不了。等 10 秒再点，已下的有缓存 |

## 排查过程复盘

> 记录这段是因为：这个问题**特别容易被误判成网络问题**，我前面走了两小时弯路。

1. 先解决两个表层问题：装数据包、开渲染开关
2. **以为是网慢** → 换线路、调连接方式、改设置，全都没用
3. **以为是服务器排队** → 看到「上传 568 KB、下载 5 KB、速度 0」，判断成对面不回话
4. **翻 UE 日志** → 发现连接在握手阶段就被切断；换条线路后链路实测很好（0.44 秒握手完成），**绑定还是失败** → 到这一步才怀疑：根本不是网络
5. **查插件清单** → 发现登录插件没开，但开了以后仍报「参数无效」
6. **做对照实验** → 新建英文项目，登录模块一次启动成功，绑定 83 秒跑完
7. **回到正式项目改名** → 日志立刻变成 `ProductName=Character` + `Login complete: EOS_Success`，绑定恢复
8. **事后复测** → 换另一种网络方式再跑一遍，同样成功，证明网络不是关键变量

> **教训**：遇到「云端功能不工作」，**第一件事是看日志里登录模块起来没有**，而不是先怀疑网速。一个 `EOS_Initialize failed` 就能省掉两小时折腾。
